## Admin cockpit (`/admin`)

The operator surface, gated whole by Basic Auth ([middleware.ts](../../middleware.ts), user `rob` + `ADMIN_PASSWORD`). Cleaned up 2026-06-23 (designed via `/brain elon-musk` → `/debate`, a delete-first pass): collapsed a flat ~10-link nav — a separate top-level page per queue — into one **Inbox** front door + a four-group nav.

- **`/admin` → `/admin/inbox`.** The **Inbox** ([app/admin/inbox/page.tsx](../../app/admin/inbox/page.tsx)) is the front door: one **read-only ranked list** unifying the five review queues — submissions, posters, verification, feedback, and agent proposals — each row a type chip + the agent's headline/verdict + age, drilling into that source's existing page to actually act. Its nav badge ([app/admin/layout.tsx](../../app/admin/layout.tsx)) is the single total across all five. Ranked by recency for now (stakes-weighting is a deliberate later increment). **It routes, it never writes** — a shared `dispose()` handler is a later step, built only if the per-source pages prove insufficient.
- **Slimmed nav (4 items): Inbox · Pulse · Analytics · Newsletter** ([components/admin/AdminNav.tsx](../../components/admin/AdminNav.tsx)).
  - **Pulse** — the read-only agent + growth surfaces under one tab via [components/admin/PulseTabs.tsx](../../components/admin/PulseTabs.tsx): **Today** (chief-of-staff ops digest) + **Growth memo** (both tabs of `/admin/briefings`) + **Experiments** (`/admin/experiments`, the growth-agent memory) + **Venues** (`/admin/venues`) + **Artists** (`/admin/artists`, the band-blurb review queue — `PRD-artist-descriptions.md`) + **Scrapers** (`/admin/scrapers`, pipeline health).
    - **Venues** is a content **backlog** (not a triage queue, so it stays out of the Inbox): review/edit each venue's **blurb and street address**. Both are auto-suggested for any venue missing one (a daily job researches the address into `address_draft`, a daily job drafts the blurb into `blurb_draft`); the curator approves/edits/discards each, and a human Save is the only path that writes the live `address`/`blurb`. Approving an address also shows a copyable `scripts/lib/venues.ts` snippet to commit (so it survives a registry re-seed). The Pulse **Venues** tab is badged with the count of venues missing a blurb **or** address (`PulseTabs` fetches it, so the badge shows from any Pulse tab).
    - **Scrapers** (`/admin/scrapers`, 2026-07-09) is the operational-health surface for the daily scrape pipeline itself, distinct from the *content*-quality surfaces above: recent-runs table, a 14-day per-source rollup (inserted/updated/error counts, currently-broken sources called out up top), an **insert-rate anomalies** callout, and a weekly narrative memo. Backed by **`scrape_runs`** (migration `20260709_scrape_runs.sql`, service-role RLS), one row per `scripts/scrape.ts` run written by [scripts/lib/scrape-run-log.ts](../../scripts/lib/scrape-run-log.ts) — instrumented at the single choke point every scraper writes through (`upsertEvents` in `scripts/lib/dedup.ts`), so no per-scraper file needed touching and any future scraper is covered automatically. The summary is written **right after the scraper loop, before the slower URL-validation pass** — the failure mode this closes: a GitHub Actions runner-timeout kill reports as `cancelled`, not `failure`, so the workflow's own `if: failure()` alerting (and, before this shipped, all scraper health data) silently never ran. Pure shaping in [lib/scraper-health.ts](../../lib/scraper-health.ts) (locked by `scripts/test/scraper-health.test.ts`). **Logging was silently dead 2026-07-09 → 2026-08-09:** `20260709_scrape_runs.sql` was `CREATE TABLE IF NOT EXISTS` and prod already carried a per-source prototype table of that name, so the migration no-opped and every summary insert failed inside the writer's best-effort catch — zero rows, an empty admin panel, and a memo reasoning over nothing (which is why the Murphys Irish Pub phantom inserts never surfaced here). Fixed by migration `20260809_scrape_runs_reshape.sql` (prototype rows preserved as `scrape_runs_prototype_2026_06`); lesson in LESSONS.md. **A sensor that can fail silently is not a sensor (HWY-18):** the `scrape_runs` insert itself now fails LOUD — a write failure posts a Slack alert (`SLACK_WEBHOOK_URL`) in `finishScrapeRun`, not just a `console.error`, so this exact blind spot can't recur invisibly. **Insert-rate anomalies (HWY-18):** `findInsertRateAnomalies` flags any source whose per-run `inserted` count has a sustained MEDIAN ≥5 across ≥3 runs (steady state is ~0-3/run; the Murphys Irish Pub phantom-lineup case, above, was exactly this shape and nothing flagged it because the scraper never errored), surfaced as an amber callout on the page and fed into the weekly memo's `watching` bucket. The weekly memo (`/api/agent/scraper-health-memo`, Mondays 18:30 UTC) is a fourth `agent_runs` flavor (`run_type='scraper_health'`, reusing the plain `Digest`/`DigestItem` shape the chief-of-staff digest already uses) reasoning over the last 14 days: needs_you = sources broken right now, fyi = the week's overall shape, watching = sources running clean but adding nothing, or a sustained high insert-rate anomaly (possibly a silently-changed page, or an extractor inventing rows). Read-only, like every cockpit reasoner — it reports, it fixes nothing. "Run now" regenerates only the narrative; the underlying `scrape_runs` rows come solely from the daily GitHub Action.
  - **Analytics** — the **Growth** tab (`/admin/analytics`), ordered North-Star-first: visitor-vs-local + business referrals + signups→visits (Gate 0), then Newsletter, then a demoted **Traffic detail** group (Cloudflare RUM; countries/devices sit in a low-signal "Audience" cut). **Reader-selected date range (2026-08-25):** a `?range=` segmented control (7d / 30d / 90d / 6mo / 12mo, default 30d) threaded through every panel — the page used to hardcode a 30-day window and a 14-bar trend chart, so the months already banked in `analytics_daily` (from 2026-05-28), `site_events` (from 2026-06-08) and the `seo_snapshots` date spine were fetched and thrown away. Server-rendered `<Link>`s, so the page stays a server component and a range is a shareable URL. Pure rules in [lib/analytics-range.ts](../../lib/analytics-range.ts) (locked by `scripts/test/analytics-range.test.ts`): **`bucketSizeFor`** collapses a long range into whole-week bars once it would exceed 30 columns (182 daily bars is an unreadable smear; a bucket is always 1 day or a whole week, never an arbitrary 5-day lump), and **`bucketSeries`** buckets from the NEWEST end backwards so any short bucket is the OLDEST one — a partial week at the right edge would read as a traffic collapse. Above 20 columns the per-bar value labels are dropped and the tooltip carries the exact counts. **Every heading states the window the data ACTUALLY covers, not the one that was clicked**: picking 12mo over 89 days of snapshots renders "89d" (same honesty rule the Gate 0 panel already applied to `site_events`). Two things deliberately stay fixed: the GSC **totals + month-over-month** cards (the collector captures a 28d cut, so a longer range can't restate them — only the by-date trend chart extends), and the `SHORT_WINDOW_DAYS` (7d) recency stat, which is capped by the range but not scaled with it.
  - **Newsletter** (`/admin/newsletter`) — the Wed-draft / Thu-send + Fri-resume veto surface, plus a **confirm-reminder** panel (HWY-43): pending-unconfirmed signups older than 24h, each with a Gmail compose draft. Rob sends; the app never does.
- **The five former queue routes still exist** — `/admin/submissions`, `/admin/posters`, `/admin/verification`, `/admin/feedback`, `/admin/actions` — and hold all the real disposition logic (publish / merge / dismiss / approve / revert, in each page's `actions.ts`). The Inbox links into them; they're just no longer top-level nav, so drilling into one keeps the **Inbox** tab lit.
- **"This didn't happen" feedback proposes a cancellation (#384).** `/api/events/feedback` still saves the note on `event_feedback`. When the note says the listing did not happen, was cancelled, or was closed ([lib/feedback-cancel.ts](../../lib/feedback-cancel.ts), locked by `scripts/test/feedback-cancel.test.ts`), the route inserts one `proposed` `agent_actions` row (`type='cancel_event'`) and skips Slack. Approval at `/admin/actions` sets `status='cancelled'` on that occurrence only (`cancelEventWritePayload`); the slug and every `*_locked` column stay as they are. Other upcoming dates of the same name and town are listed on `series_event_ids` for the reviewer. There is no `agent_policy` row, `canAutoExecute` cannot pass (`blast_radius='med'`, `outward_facing=true`), and `isAutoReady` returns false, so the auto-runner cannot cancel a listing. Revert restores the previous `status` from `before_snapshot` and nothing else.
- **A scrape that throws or never runs files the same queue (#345).** Those rows are also `proposed` `agent_actions`, type `schedule_watch_alert` with `payload.alert` `scrape`. They sit beside a `cancel_event` row and do not share its executor. Reject dismisses one. Approving it does not change events. The fingerprints are in [Event sources](event-sources.md).
- **Agents file dev tickets as GitHub issues (#325).** The weekly QA audit and the growth memo write `proposed` issues to the public repo through `GITHUB_ISSUES_TOKEN` ([lib/github-issues.ts](../../lib/github-issues.ts)); the chief-of-staff digest files none. The repo is public, so the growth-memo prompt bars private numbers and names, and `privateSignal` in [lib/agent/propose-tasks.ts](../../lib/agent/propose-tasks.ts) holds back any proposal that still carries an email address or any digit other than public tokens (the site's name and road, an ISO date, a 2024-2029 year in a year-shaped position, an issue/board ref) or a spelled-out number from two up or "percent" (`privacy_hold`). Held proposals go to the Inbox alert instead of GitHub. Known gaps, accepted: people's names, "one", figures phrased without a number, and a count in a year position pass (the prompt rule is the only guard there); an HTTP code is held as a false positive. Both writers stop filing 15s before their route's limit (`deadline_exceeded`; QA audit at 45s of 60, growth memo at 105s of 120), and the growth memo's extraction call is time-boxed to that budget too, so the Inbox alert still lands when GitHub or the model is slow. When their findings do not reach GitHub (token unset or expired, list or create failed, `proposed` label dropped), each files one proposed `agent_actions` row, type `issue_filing_alert` ([lib/agent/issue-filing-alert.ts](../../lib/agent/issue-filing-alert.ts)), naming the unfiled titles and any issue that lost its label. One open row per source; a later failure merges its items into that row rather than dropping them. Reject dismisses it. Approve has no executor, so it marks the row `failed` with an "Unknown action type" flash, the same as `schedule_watch_alert`; use Reject.

## Weekly PM pass (a scheduled task, NOT a Vercel cron)

The cockpit had five proposers and no closer. Measured 2026-07-29: 11 growth memos had produced 7 tickets (5 shipped), the board was drained to **0** open tickets, three `growth_experiments` had been `running` for 33 to 52 days, and `growth_lessons` held **0** rows. `lib/agent/growth-lessons.ts` (HWY-5) only distills a lesson from a *concluded* experiment, so the growth agent's memory loop had never once fired and every Friday memo reasoned from scratch.

**[.claude/skills/pm-review/SKILL.md](../../.claude/skills/pm-review/SKILL.md)** is the closer. It concludes experiments that are past a 28-day eligibility floor: translate the prose `metric` field into aggregate SQL, compare the window since `started_on` against an equal-length window before it, and write `status` + `result` + `concluded_on`. The next Friday memo then captures those into `growth_lessons` via the existing `captureLessonsFromConcludedExperiments` and reads them back in the same run, so **nothing new writes lessons** and the loop closes in ~24h.

**It runs as a Cowork scheduled task** (`~/.claude/scheduled-tasks/hwy4-pm-weekly/`, Thursdays ~8:30am PT, ahead of the Friday memo), not a Vercel route, because rendering an honest verdict needs a repo and a shell: the metric is prose that has to become SQL, and `git log` over the window is how you catch a confounder. The cron reasoners have neither. Same shape as `hwy4-persona-qa-daily`: the task file only pulls the repo and delegates, and the *spec* is the repo-committed skill, versioned alongside the code it reasons about.

Writes an `agent_runs` row with `run_type='pm_review'`. **Verdict bias is deliberate: default to `inconclusive`.** Weekly volumes here are small, and a lesson gets injected into later prompts as ground truth, so a flattering `won` poisons every future memo. Same never-guess contract as the price extractor and the artist-blurb drafter. It may never write `abandoned` (killing an experiment is Rob's call), never touch `hwy4_events`, never publish, never push code. Every conclusion reverts with one `update`. PRD-ifying tickets and ranking the board are later phases, explicitly out of scope.

**First run (2026-07-30) concluded all three stale experiments `inconclusive`, and none for a boring reason:** the live-music venue-section test was confounded (clicks per event-detail session fell 0.0344 → 0.0160 while sessions grew 4.5x once Google organic started Jun 19, mid-baseline, so the ratio measures audience mix; its secondary metric was met at 209/214); the after-event-5 signup box had no valid baseline (all 79 prior rows predate source tagging) and the real finding was comparative, `event_detail` placement out-producing `homepage_event5` in half the time; and the host kit was never distributed (**zero** `src=host` events ever, `/hosts` drew 5 views and none since Jun 18), so it is untested rather than failed. Two experiments declared metrics their own instrumentation could not measure at their start, which is the process lesson: **an experiment needs a horizon and a baseline snapshot at creation time.**

Migration `20260729_agent_runs_pm_review.sql` shipped with it and fixes **two latent bugs found while wiring this up**, both of which had silently disabled a documented feature:

1. **`agent_runs_run_type_check` only allowed `chief_of_staff|growth_memo`.** `/api/agent/scraper-health-memo` has inserted `run_type='scraper_health'` since it shipped, so every Monday it burned a Sonnet call, had its insert rejected, failed its error-path insert the same way, and 500'd. `/admin/scrapers` (the Pulse "Scrapers" tab) had therefore never rendered a memo. Zero `scraper_health` rows existed as proof.
2. **`growth_lessons_experiment_uq` was a PARTIAL unique index** (`WHERE source='experiment' AND source_ref IS NOT NULL`) while the capture upserts with `onConflict: "source_ref"`. This is the identical gotcha already documented for `seo_snapshots`: **PostgREST `onConflict` cannot name a partial index.** Postgres raised 42P10, the capture caught it and returned 0, so the memory loop could not have written a lesson even once an experiment was concluded. Concluding experiments alone does not close the loop. Replaced with a plain unique index (NULLs are distinct, so manual lessons are unaffected); verified with a rolled-back `on conflict (source_ref)` probe against prod, failing before and inserting after.
