## Cron Jobs (vercel.json)

| Route | Schedule | Purpose |
|---|---|---|
| `/api/generate-briefing` | Daily 8am UTC | Generate daily briefing via Opus. Runs at 08:00 UTC (1am PDT / midnight PST) — the earliest time safely past Pacific midnight, so the route's UTC-based "today" still matches Pacific's today while the pre-regen "yesterday's briefing" window early risers see shrinks to ~1hr. Do not move earlier than 08:00 UTC or UTC-today will advance while it's still the prior evening in Pacific. |
| `/api/check-briefing` | Daily 5pm UTC | Verify briefing was generated |
| `/api/generate-weekend-briefing` | Thursdays + Fridays 2pm UTC | Weekend briefing (Opus). Friday writes the following Fri–Sun ("Next Weekend") via `upcomingWeekendPreview` in [lib/date-windows.ts](../../lib/date-windows.ts) (Pacific: Mon–Thu → coming Friday, Fri–Sun → the Friday after) and is the one `briefing_history` row for that weekend. Thursday refreshes the same window once it is "This Weekend": rewrites `site_config` (text, `weekend_briefing_date`, label) and does **not** insert a second history row, so the anti-repetition lookback does not argue with the draft it is replacing and Thursday's daily archive is left alone. One extra Opus call a week. The homepage footer stamps whichever tab is open (`formatBriefingUpdated`). The CANCELLED EVENTS prompt section is filtered through `realCancellations` ([lib/briefing-cancellations.ts](../../lib/briefing-cancellations.ts)): a `status='cancelled'` row is dropped when `event_merge_log.merged_from_id` names it, or when a non-cancelled row on the same date and town carries a similar title, because Phase 0 dedup tombstones share that status with real organizer cancellations and the 2026-10-09 briefing called the Murphys Gathering (a Rob's Pick) cancelled (issue #405). A failed merge-log read drops the whole section. Locked by `scripts/test/briefing-cancellations.test.ts`. |
| `/api/newsletter/prepare` | Wednesdays 3pm UTC | Generate the weekly newsletter body and store it as a **pending** `newsletter_drafts` row for the coming Thursday, then Slack-ping a review link. Writes a draft only — never emails. Idempotent per target Thursday; won't clobber a vetoed/edited draft unless `?force=1`. |
| `/api/newsletter/send` | Thursdays 3pm UTC | Ship the week's newsletter on a **24h veto window**: auto-sends today's `newsletter_drafts` row *unless* a human vetoed it at `/admin/newsletter` (the ~24h between Wed prepare and Thu send). No draft at all (prepare didn't run) → sends nothing and Slack-warns; it never auto-generates-and-blasts unsupervised. **Two-wave free-tier cap (HWY-44):** `sendCampaign` hard-stops after `NEWSLETTER_DAILY_SEND_BUDGET` (85) successful-attempt recipients in one run so confirm/reminder/test mail still fits under Resend's 100/day team quota. Recipients are ranked local/hub → proven recent clickers → newest confirmed before the slice. The draft stays `pending` (sent_count updated, body archived) while remainder > 0; it is marked `sent` only when the eligible list is drained. `?preview=1` renders the current draft (no auth, no send); `?test_email=…` generates fresh + sends to one address (template smoke-test, bypasses the gate). **Send reliability (ledger-backed since 2026-07-03):** delivery runs through the idempotent `sendCampaign` (`lib/newsletter-send.ts`) over a durable per-recipient ledger — `newsletter_send_log`, `UNIQUE(campaign_id, email)`, migration `20260703_newsletter_send_log.sql`, design adopted from Peter Hollens's Eugene fork per `HANDOFF-newsletter-reconcile.md`. Each batch is pre-marked `pending`, shipped via the Resend **Batch API** (≤100/request, permissive validation + a per-chunk idempotency key), and every per-recipient result is upserted over its ledger row; a throttled (~2/sec `SEND_THROTTLE_MS`) retry pass covers transient failures, and `newsletter_suppressions` addresses are skipped. **Re-running the route while the draft is still `pending` RESUMES the send** (the ledger skips everyone already `sent`) — re-blasting is structurally impossible, and a crash/timeout mid-send recovers by just re-hitting the cron URL. Real shortfalls (failures, stuck-`pending` rows) log + Slack-alert with addresses; an intentional budget remainder is a wave note, not a failure. **Recovery: `POST` to the same route** with `{ "targets": ["…"] }` (CRON_SECRET-gated) re-sends the in-flight pending campaign if one exists, else the most recent *sent* issue, to an explicit address list through the same ledger-backed send — active subscribers only, ledger-deduped (pre-ledger issues have no rows and send as before), real per-recipient unsubscribe links. |
| `/api/newsletter/send?resume=1` | Fridays 3pm UTC | **Resume cron (HWY-44).** Same handler as Thursday (`?resume=1` is only so the cron path is distinct). Picks any still-pending `newsletter_drafts` row with `target_send_date` before today (yesterday's leftover), sends up to the daily budget of remaining not-yet-sent recipients (ledger skip-if-sent, suppressions, pending-block unchanged), same subject/HTML. Marks the draft `sent` when remainder is 0. Quiet skip (no Slack) when there is nothing to drain. |
| `/api/scrape-bls` | Mondays 1pm UTC | Scrape Blue Lake Springs flyer images via Vision AI |
| `/api/scrape-moose-lodge` | Mondays 2pm UTC | Scrape Ebbetts Pass Moose Lodge monthly PDF calendar via Claude PDF document API. Replaces the deprecated `scrape-moose-lodge` Supabase edge function (2026-05-26). **Manual override:** pass `?pdf_url=<url>` to run the same pipeline against an off-site PDF when the lodge's `/current-calendar` page still serves last month's calendar (they lag at month-start; the July 2026 calendar shipped via their Drive newsletter before their site updated). Google Drive `…/file/d/<id>/view` share links are auto-normalized to a direct download. An override run is **additive-only — it skips the stale-row sweep** (a partial/newsletter PDF must not delete real rows). `curl -H "Authorization: Bearer $CRON_SECRET" "https://hwy4events.com/api/scrape-moose-lodge?pdf_url=..."`. |
| `/api/verify-events` | Daily 3pm UTC | Cross-check upcoming events against organizers' canonical sites; flag mismatches as `needs_verification` |
| `/api/extract-prices` | Daily 1:30pm UTC | Extract explicitly-stated admission fees from event description/name into `price` + `cost_tier` via Haiku. Only lifts fees that are stated, never guesses. Processes 40/run by default; `?limit=150` for manual backfill. Stamps `price_extracted_at` so events aren't reprocessed. |
| `/api/reconcile-dupes` | Daily 3:30pm UTC | Self-healing event identity: clusters resident `hwy4_events` rows via the shared matcher and merges duplicates (back-fill survivor, snapshot loser to `event_merge_log`, delete loser). Covers every write path including the raw-insert writers. **Live since 2026-07-01** (`RECONCILE_EXECUTE=true`); unset env = dry-run, `?execute=1` = one-off. After scrapes, before the audit. |
| `/api/indexnow` | Daily 4pm UTC | **IndexNow push (HWY-62).** After the 15:30 reconcile (so a merged-away duplicate is never submitted), POSTs to `api.indexnow.org` every public, non-routine, non-cancelled upcoming event **created** in the last ~24h (a 25h window, so a late cron drops nothing) plus the hub pages it changes (`/`, the temporal pages, `/live-music`) and each published town page that gained an event. Not keyed on `updated_at`, which churns daily. Pure core in [lib/indexnow.ts](../../lib/indexnow.ts) (dedupe, same-host filter, 10,000-URL batches, never throws), locked by `scripts/test/indexnow.test.ts`. The key is public by design, served at `/indexnow-key.txt` ([app/indexnow-key.txt/route.ts](../../app/indexnow-key.txt/route.ts)) and passed as `keyLocation`; it comes from `REGION_OPS.seo.indexNowKey`, overridable with `INDEXNOW_KEY`. Verify in Bing Webmaster Tools → IndexNow. |
| `/api/snapshot-analytics` | Daily 9am UTC | Snapshot the previous UTC day of Cloudflare Web Analytics (RUM) into Supabase `analytics_daily` via `lib/cloudflare-analytics.ts`. Builds unbounded local history (CF's RUM GraphQL API serves only ~3 weeks back — unsampled just 7 days — so this snapshot is the system of record) + answer-engine referral counts. **RUM spike guard (2026-09-10):** before upsert, `judgeRumSnapshot` rejects a day whose `pageviews` or `visits` is ≥10,000 (the adaptive-groups ceiling) or whose totals are ≥10× that snapshot's referrer-row visit sum. Rejected days are still written (gap visible) with `rejected=true`, `reject_reason`, and **null totals** — never a guessed replacement count. Idempotent upsert on `date`; `?date=YYYY-MM-DD` backfills a specific day. Needs `CLOUDFLARE_*` env. See PRD-cloudflare-analytics.md. |
| `/api/check-events` | Daily 6pm UTC | Data-quality audit on `hwy4_events`: duplicates, hidden rows, missing fields, stale scrapes, plus `merges_last_24h`. Also **data-plausibility checks** ([lib/audit-checks.ts](../../lib/audit-checks.ts), locked by `scripts/test/audit-checks.test.ts`, added after the 2026-07-16 persona QA passes): `impossible_times` (zero-length windows, end-before-start, lone small-hours starts — backstops the raw-insert writers that bypass `normalizeEventTimes`), `category_inconsistencies` (one production carrying several categories across its rows), and `timeless_near_dupes` (same-day same-venue clusters involving a NULL-start row), and `venue_slot_collisions` (added 2026-08-09: ≥2 different-named public events starting within ~30 minutes at one **single-operator** venue — the only tripwire for a scraper inventing rows or stranding a rebooked night, since different named acts are exactly what the matcher must never merge; multi-tenant venues and routine/members-only rows excluded). **HWY-10 fixed the structural cause** — see "Festival umbrella rows" — so a steady state of zero is now the expectation rather than a permanent backlog; marked `series_umbrella` rows are excluded, and the check remains as the backstop for pairs the matcher deliberately declines (one side's venue unknown, or no identity signal firing). Also an **analytics-snapshot freshness alarm**: reads the latest `analytics_daily` row and alerts if it's ≥2 days behind (the daily snapshot cron may be failing) or the latest captured day has 0 pageviews (the CF read silently failed) — durable history can't be backfilled past CF's ~3-week API window. Posts to Slack if `SLACK_WEBHOOK_URL` is set (the existing audit post; a missed scrape does not add a Slack line). Read-only against `hwy4_events`. Two monitoring writes: the compact summary to `site_config` key `latest_audit_summary` (shape in [lib/agent/audit-signal.ts](../../lib/agent/audit-signal.ts), including `scrape_run_overdue`) so the chief-of-staff digest an hour later sees the same backlog, and a proposed `agent_actions` row (`schedule_watch_alert`, `payload.alert` `scrape`) when the newest `scrape_runs.started_at` is missing or older than 30 hours (`scrapeRunIsOverdue` in [lib/audit-checks.ts](../../lib/audit-checks.ts)). A failed `scrape_runs` read does not file that row. Fingerprints for a thrown source, a nulled-link jump, and a spared host are in [Event sources](event-sources.md). |
| `/api/aeo-audit-reminder` | 1st of month, 8am PT (16:00 UTC) | Posts the monthly AEO prompt-audit checklist to Slack (`SLACK_WEBHOOK_URL`). Manual ritual — a human runs the 13-query bank against AI engines and logs results in `AEO-SEO-MEASUREMENT.md`. Read-only. |
| `/api/sync-venue-facts` | Mondays 12pm UTC | Refresh `hwy4_venues` live facts (rating, review count, phone, website, hours, Maps URL) from the Google Places API (New). `place_id` is resolved once and cached; the rest refresh weekly. Needs `GOOGLE_PLACES_API_KEY`. `?limit=` to cap the batch. `?only=new` syncs only never-synced rows (the daily new-venue onboarding pass below). |
| `/api/sync-venue-facts?only=new` | Daily 11:30am UTC | **New-venue Places onboarding.** Same route, `only=new` mode: syncs Places facts for venues with `places_synced_at IS NULL` only, so a freshly-added venue gets its `place_id` + facts within a day instead of waiting for the weekly full refresh (and the 1pm blurb drafter, which needs `place_id`, can then draft it same-day). Skips the weekly staleness refresh, so it doesn't re-bill the whole registry daily (Google's free credit is sized to the weekly cadence). Idempotent: once synced, a row drops out of the never-synced set. |
| `/api/agent/draft-venue-addresses` | Daily 10am UTC | **Self-healing venue ADDRESS drafter** (sibling to the weekly→daily blurb drafter). For any `hwy4_venues` row with no `address` (and not `places_locked`), web-researches the Tier-A street address (`lib/agent/research-venue.ts` via `lib/agent/draft-venue-addresses.ts`, Sonnet + `web_search`) and stages it as a **pending** `address_draft` for human review at `/admin/venues`. **Advisory only — never writes the live `address` column** (a human Save does, same accuracy contract as blurbs). Idempotent + self-limiting: `address_draft_at` is stamped even on an empty result, so a venue with no findable address isn't re-researched daily. `?limit=N` caps the batch (default 6). Migration `20260630_venue_address_drafts.sql`. |
| `/api/agent/draft-artist-blurbs` | Daily 10:30am UTC | **Self-healing artist/band-blurb drafter** (`PRD-artist-descriptions.md` Phase 1, the band sibling to the venue blurb queue). For each distinct act named in the `artists` field of an upcoming public `live_music` event that has no resolved `hwy4_artists` row, web-researches the act (`lib/agent/research-artist.ts` via `lib/agent/draft-artist-blurbs.ts`, Sonnet + `web_search`) and stages a **pending** `blurb_draft` (genre + two-sentence local-voice prose + outbound links) for human review at `/admin/artists`. **Conservative by design — errs on nothing:** a low-confidence or sourceless result yields no prose/genre (enforced in code, not just the prompt), because a wrong band's bio is worse than a blank; it always tries to surface the act's website/Facebook. **Split policy (standing rule — Rob, 2026-08-11): a HIGH-confidence result with prose auto-publishes the live `blurb`/`genre`/`links` and Slack-informs (no approval); medium and below stage a `blurb_draft` a human Save publishes** (`lib/agent/artist-autopublish.ts`, locked by `scripts/test/artist-autopublish.test.ts`; the 28-draft high-confidence backlog was published the same day). Venue blurbs keep their full human gate. Idempotent + self-limiting: `blurb_draft_at` stamps even on an empty result. `?limit=N` (default 6). Migration `20260720_artists.sql`. Links by normalized name (no column on `hwy4_events`). |
| `/api/check-lube-schedule` | Mondays 4pm UTC | Fingerprints the Shopify CDN images on [theluberoom.com/pages/events](https://www.theluberoom.com/pages/events). If the "Live at the Lube" schedule graphic changed, posts to Slack so a human can update + re-run `scripts/seed-lube-room-summer-2026.ts`. The venue's schedule is image-only / hand-curated and blocklisted from the auto-scrapers, so this **never writes events** — it only watches. State in `site_config.lube_schedule_fingerprint`. |
| `/api/check-bigtrees-schedule` | Mondays 5pm UTC | Fingerprints the interpretive-program **list** on [parks.ca.gov ?page_id=25994](https://www.parks.ca.gov/?page_id=25994) (not the intro; a page that still has the intro and no list is a missing schedule). On a change or a missing list, inserts a `proposed` `agent_actions` row (`type='schedule_watch_alert'`, payload in `lib/bigtrees-watch.ts`) for the cockpit bot. It does not post to Slack and **never writes events**. State in `site_config.bigtrees_schedule_fingerprint` (`missing` when the list is gone). Re-transcribe `scripts/lib/bigtrees-schedule.ts` and re-run `scripts/seed-bigtrees-programs-2026.ts`; the seed skips dates already `cancelled`. |
| `/api/check-camp-connell-schedule` | Mondays 5:30pm UTC | Fingerprints the Squarespace CDN images on [campconnellgeneralstore.com/events](https://www.campconnellgeneralstore.com/events). | `/api/check-murphys-senior-center-schedule` | Mondays 6pm UTC | Fingerprints the WordPress calendar images on [murphyscenter.com/calendar](https://murphyscenter.com/calendar/) — the center publishes its schedule only as monthly calendar/newsletter PNGs. State in `site_config.murphys_senior_center_schedule_fingerprint`. |
| `/api/agent/triage-submissions` | Daily 6:30pm UTC (before the 7pm digest) | **Agent Cockpit Stage 1 (submissions) — backstop.** Triages every pending, un-analyzed `event_submissions` row (`ai_analyzed_at IS NULL`) via `lib/agent/submission-triage.ts`: shared-matcher DB dedup + Anthropic `web_search` + Sonnet verdict, written back to the row. The primary trigger is `after()` on `/api/submit-event`; this catches anything that missed. `?id=<uuid>` (re)analyzes one, `?force=1` re-runs an analyzed one. **Advisory only — never publishes or writes to `hwy4_events`.** |
| `/api/agent/expire-submissions` | Daily 7:30am Pacific (`30 14 * * *`, 7:30am PDT / 6:30am PST) | **Clear past pending submissions.** Rejects `event_submissions` where `status='pending'` and `event_date` is before the Pacific civil date (`pacificToday`), sets `review_note` to `Expired: event date passed without review`, and emails the submitter when `submitter_email` is present and triage did not flag `possible_spam`. Copy is the fixed `expired` outcome in `lib/agent/submission-reply.ts` (no model call), sent through Resend with `newsletterFromHeader` / `newsletterReplyTo`. Stamps `ai_reply.auto_sent` so `/admin/submissions` does not offer a Gmail compose for mail already sent. Idempotent (already-rejected rows are untouched). Does not publish and does not email Rob. `?dry_run=1` counts only. Quiet slot: nothing else uses 14:30 UTC (the :00 of that hour is the Thu/Fri weekend briefing and the Monday moose-lodge scrape). |
| `/api/agent/collect-seo` | Daily 11am UTC | **Search Console collector (Agent Cockpit Stage 0).** Pulls Google Search Console performance in three cuts and writes `seo_snapshots`: a by-date trend spine (**upserted** on `(source, data_date)`, self-correcting as GSC revises recent days), plus by-query and by-page top-500 snapshots (point-in-time inserts). Runs before the growth-memo (Fri 16:00) and chief-of-staff (19:00) so both read same-day data. Zero-dep GSC client `lib/agent/gsc.ts` (`fetchGscCuts`); dormant no-op until `GOOGLE_SEARCH_CONSOLE_SA_JSON` is set. `?history=NNN` (28–480) seeds the by-date spine over a longer window (one-time backfill). Read-only. See "Search Console (SEO analytics)" below. |
| `/api/agent/chief-of-staff` | Daily 7pm UTC (after the 6pm audit) | **Agent Cockpit Stage 0 reasoner.** Reads the verification queue, pending `event_submissions` (incl. their `ai_verdict`/`ai_headline`), 24h auto-merges, the latest `seo_snapshots`, and the **Rob's Picks runway** (`lib/agent/picks-runway.ts`: days until the hand-curated homepage picks section goes empty, counting live festival guides; a deterministic `needs_you` nudge is appended when ≤7 days remain or it's already empty, locked by `scripts/test/picks-runway.test.ts`), and **yesterday's data-quality audit** (`lib/agent/audit-signal.ts` reads the `site_config` summary `/api/check-events` stashes an hour earlier; a deterministic `watching` backlog item / `needs_you` alarm is appended if the model skips it, locked by `scripts/test/audit-signal.test.ts` — added 2026-07-11 after the digest headlined "all quiet" beside a 26-item audit post), asks Sonnet (`claude-sonnet-5`) to triage them into a short digest, writes one `agent_runs` row (`run_type='chief_of_staff'`), and posts a one-liner to Slack linking `/admin/today` (headline says "nothing urgent, N backlog item(s)" instead of "all quiet" when the audit backlog is nonzero). **Read-only: proposes/executes nothing.** See `PRD-agent-cockpit.md`. |
| `/api/agent/propose-actions` | Mondays 7:30pm UTC | **Agent Cockpit Stage 1 — link-gap + venue-gap proposers.** (1) Reads the shared `actionable_link_gaps` worklist (`lib/link-gaps.ts`, the same definition `/api/check-events` uses) and stages one `proposed` `create_org_row` per single-operator venue needing a durable link — pre-filled except the canonical URL. (2) Reads the venue-gap worklist (`lib/venue-gaps.ts`: unregistered venues — `venue_key IS NULL` + a real, non-generic name not already a registered canonical — with ≥3 upcoming public events) and stages one `create_venue_row` each, web-researching the Tier-A street address (`lib/agent/research-venue.ts`). Idempotent; **proposes only, never executes.** A human disposes each at `/admin/actions`: approve `create_org_row` → insert `hwy4_orgs` row (reversible: delete); approve `create_venue_row` → insert `hwy4_venues` row (reversible: delete) **and commit the emitted `scripts/lib/venues.ts` snippet** to link the venue's events durably (the matcher is registry-driven, so the row alone lights up the venue section + Places facts, but events stay unkeyed until the commit). Also runnable via the page's "Scan" button. See `PRD-agent-cockpit.md`, `PRD-live-music-experience.md`. |

Advisory only — a human promotes each at `/admin/roadmap`. `lib/agent/qa-audit.ts` (`checkPage` locked by `scripts/test/qa-audit.test.ts`). Slack-pings when it files. See `PRD-roadmap-board.md`. |

| `/api/agent/growth-memo` | Fridays 4pm UTC | **Growth Agent (Phase 1) — weekly Head-of-Growth memo.** Reads the growth signal pack (`lib/agent/growth-context.ts`: newsletter net + confirm-rate leak, weekly local-session WRR proxy from `site_events`, visitor business-referrals, traffic/SEO, organizer network, share/poster virality) and asks Sonnet to write one memo: the North Star read, **the single highest-leverage move this week (drafted as ready-to-send copy)**, experiments in flight, and a demoted ops footer. Distinct from the daily chief-of-staff ops digest. See `PRD-growth-agent.md`. |

All cron routes require `CRON_SECRET` as a bearer token. To smoke-test any cron route manually:

```sh
curl -H "Authorization: Bearer $CRON_SECRET" https://hwy4events.com/api/<route>
```
