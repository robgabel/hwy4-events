## Deduplication (defense in depth)

The same real-world event can appear twice: one source re-lists it under a changed title, or two sources describe it independently (e.g. the GoCalaveras aggregator lists "Live Music @ The Lube Room" while the venue feed lists "Live at The Lube: Poison Oakies" — same night). The title-based `dedup_key` only catches byte-identical re-scrapes of the *same* title, so it cannot see these. Three layers guard against dupes (a fourth, read-time, was retired 2026-08-23 — see layer 1):

> **Measured 2026-09-27, see [PRD-dedup-merge-v2.md](../../PRD-dedup-merge-v2.md) for the phased fix.** The layers below leak in three measured ways. (1) The ~7.5h transit bound in layer 1 holds only for pairs the matcher sees on the next scrape: merged-away rows lived a median 122h, because a merge keeps one `(source_name, source_event_id, dedup_key)` and the absorbed source can no longer find the row by key, so it re-inserts on any degraded scrape (BVTS 10-10 was re-merged 5 times in 30 days; ~49 rows carry another source's `source_event_id`, where no lookup can use it). (2) The clock is a hard veto evaluated before identity: cross-source listings of a multi-hour event that disagree on the start (Murphys Gathering, 11:00 vs the organizer's 12:00) are invisible to every layer and every audit check; `same_event_duplicates` read 0 with 5 pairs live. (3) An unlisted pre-filter exists: GoCalaveras's in-scraper Sonnet `crossSourceDedup` drops aggregator events before `upsertEvents`, blind to times, with no augmentation and no log. Also latent (fixed in Phase 0): `isGenericTitle` treats "Live Music - <Act>" as a placeholder, so reconcile would merge a named act into another same-venue row within 90 minutes and keep the other row.
>
> **Phase 0 done (2026-09-28).** The 5 live pairs are merged as cancelled tombstones (reversible, `event_merge_log` signal `manual:dedup-v2 phase0 …`), so a scraper exact-matching a tombstone updates it instead of re-inserting. **`isPlaceholderForMatch`** ([lib/event-identity.ts](../../lib/event-identity.ts)) is now the placeholder test for the identity signal and survivorship: a generic prefix followed by a real act after an act separator (a dash or colon right after the prefix or with a space beside it, a parenthesis, or with / featuring / feat. / ft. / w/ / by, as in "Live Music - Jill Warren" or "Live Music with Lost in the Shuffle") is not a placeholder, while no separator, a TBD tail, the whole venue name, or filler ("Live Music - Friday Night") still is; an ambiguous tail reads as an act, which for matching can only cost a merge (for survivorship it drops the -12 penalty; authority survivorship is Phase 2). The series start tolerance deliberately stays on the broad `isGenericTitle`: keying it on the narrow test let a TBD slot pair with a different act 30 minutes earlier (the independent review's blocker on PR #304). Broad tolerance plus narrow signal means Phase 0 only ever merges less than before; a replay over every row that ever existed showed 0 new merges. `isGenericTitle` keeps its other callers unchanged. GoCalaveras's degraded re-inserts are held at the write boundary (the degraded-insert hold, under Event Sources), and a venue can register extra entrances (`KnownVenue.addresses`). Phases 1 to 3 (clock-tolerant matcher, source-key golden record, near-miss review queue) are still proposed.

1. **Read-time layer: RETIRED (2026-08-23, dedup Move 3 complete).** [lib/dedupe-events.ts](../../lib/dedupe-events.ts) once ran `dedupeEvents` as a silent collapse on every user-facing list, was downgraded to the loud non-collapsing `assertNoResidentDuplicates` (HWY-16, 2026-08-11), and was then removed from the render paths entirely — `lib/events-data.ts` and both briefing generators pass rows straight through. **The removal gate, stated honestly (the adversarial review of the removal PR forced this precision):** the week of Aug 16-22 held zero PERSISTENT duplicates (daily audits: `duplicates` 0, `same_event_duplicates` 0, `venue_slot_collisions` 0) and exactly 2 TRANSIENT ones — same-title pairs a morning scrape created and the 15:30 UTC reconcile merged the same day (`event_merge_log`, both reversible). "The assertion never fired" was NOT verified (nobody read the Vercel logs) and is probably false for those two mornings. What the removal actually accepts: a duplicate can transit the render path for up to ~7.5h (08:00 UTC scrape → 15:30 UTC reconcile — 01:00-08:30 Pacific, the corridor's lowest-traffic hours) before the self-heal, and the audit runs at 18:00 — AFTER reconcile — so by design it reports what reconcile MISSED, while its `merges_last_24h` count (+ the Slack "auto-healed" line) is the visibility for what reconcile fixed. Same-title transits surface via the exact-title `duplicates` check, not `same_event_duplicates` (which requires distinct names). The shrimp-feed lesson below still holds: `same_event_duplicates` shares `isSameEvent` with the merge layers, so a predicate regression blinds them together — the predicate-INDEPENDENT tripwires are the exact-title check, `venue_slot_collisions`, and `timeless_near_dupes`, which is what caught the Murphys Creek Theatre treadmill. `clusterEvents`/`pickSurvivor` remain (consumed by `lib/reconcile.ts`) and `findDuplicateClusters` remains (consumed by `/api/check-events`); `dedupeEvents`/`mergeCluster` survive only for the dev CLI `scripts/check-feed-dedup.ts` and as the collapse implementation should a read-time layer ever be wanted back.
2. **Write-time merge** — `scripts/lib/dedup.ts` (`isStrongEventMatch` / `buildStrongMatchUpdate`) replaces the old name-only fuzzy. When a scraped event has no `dedup_key`/`source_event_id` hit, it merges into an existing same-date/same-town row that shares an exact time slot + the same strong signal, field-merging so the survivor keeps the best of both (and unions artists). Conservative — never merges on title similarity alone. **The exact-key update path is null-guarded (HWY-29, `keepStr`): a re-scrape never writes a scraped-blank `description`/`start_time`/`end_time`/`price`/`image_url` over a stored non-blank one on an unlocked row.** This closed the "merge treadmill" — GoCalaveras titles every Murphys Creek Theatre show `"… presents"` (real name only in the URL slug, now caught by `isGenericTitle`), so a night's row merged and got back-filled by reconcile, then the next morning's aggregator pass wrote its NULLs over the enrichment and re-inserted, churning daily. Also: `pickSurvivor` (`lib/dedupe-events.ts`) breaks a richness tie toward the **older** row (`created_at`) so a fresh aggregator re-insert can't displace an enriched resident nondeterministically. Found by `venue_slot_collisions`; locked by `event-identity`/`dedupe-events` tests. **Follow-up (2026-08-16):** the guard now covers `event_url`/`address` too, `rowChanged` is defined as "what the payload WOULD write differs from what is stored" (the same `keepStr` expressions — a wipe-shaped diff no longer re-marks a row "updated" every run, which was churning the per-source updated counts on `/admin/scrapers` and holding flaky-feed sources out of the weekly memo's quiet-source bucket — expect some genuinely-quiet sources to newly appear there), the two exact-match paths share the one exported `rowChanged` (the batched twin carried a drifted inline copy missing the category self-heal), and **a placeholder title never overwrites a specific one on any write path** (`placeholderNameSteal`): before this, "whoever scraped last takes the name" let the daily GoCalaveras pass rename a properly-titled row to "Murphys Creek Theatre presents" within a day of every merge (live 2026-08-15 on the Aug-21 row) and the next Visit Murphys pass stole it back, a permanent rename ping-pong; a kept name keeps a `dedup_key` recomputed from itself, and the healing direction (specific over placeholder) still writes, so each date converges to its real title permanently. Locked by `scripts/test/null-guard.test.ts`.
> **A failed UPDATE is not an update (HWY-33, 2026-09-05).** The **serial** exact-match path (the default — `BATCH_DEDUP` gates the other) never destructured Supabase's `error` and ran `result.updated++` unconditionally, so a run whose writes were all rejected still reported them as updated, and that count is what reaches `scrape_runs.source_results`, `/admin/scrapers` and the weekly memo. The batched twin checked properly, which is the same drift family as the inline `rowChanged` copy fixed 2026-08-16. All four per-row update sites (both exact-match, both merge) now route through one exported **`countUpdateResult`**; it deliberately adds **no** error field to `UpsertResult`, matching the batched path's existing contract (log the row, simply don't count it), so the `scrape_runs` shape is unchanged and a failed update shows up as a row that is neither `updated` nor `unchanged`. `scripts/test/update-outcome.test.ts` pins the contract **and** guards the source: `countUpdateResult` is the only place allowed to bump a success counter.

> **Lineup posters and source subtitles name the act (HWY-59).** GoCalaveras stores the calendar title ("Live Music" / "Live Music @ Murphys Irish Pub") and the weekly poster as separate facts, and `evcal_subtitle` is artist/host text it must not use as the venue. `applyDiscoveredActs` ([lib/lineup-acts.ts](../../lib/lineup-acts.ts)) reads a shared lineup image (one vision call per image, several dated nights) or a single-night flyer / subtitle and stamps `discovered_act` on the existing row for that date. It does not insert a night the calendar didn't already list, and an open-mic billing is not an act. The public title keeps the generic stem and the venue so the old slug still resolves: "Kiana Chanelle Live Music @ Murphys Irish Pub". The write path (`resolveWrittenName` in [scripts/lib/dedup.ts](../../scripts/lib/dedup.ts)) applies that title only while the stored name is still an actless placeholder. A later scrape of the generic calendar title keeps the specific name (`placeholderNameSteal`) and does not clear artists. No `name_locked` column: the first specific title sticks, including against a later poster reading that names a different act, so a flaky re-read cannot rename the night every morning. Wired in the GoCalaveras scraper after classification and before its cross-source drop. Locked by `scripts/test/lineup-acts.test.ts`.

3. **Continuous reconcile (self-healing identity)** — [lib/reconcile.ts](../../lib/reconcile.ts) (`reconcileDuplicates`) operates on DB state, blind to who wrote the rows, so it covers **every** write path — the `upsertEvents` scrapers AND the three raw-insert writers (`scrape-bls`, `scrape-moose-lodge`, `bistro-espresso`) AND any future writer. It clusters resident rows with the same shared `clusterEvents`/`pickSurvivor`, back-fills the survivor from its losers, and deletes the losers — writing a full reversible snapshot to `event_merge_log` **before** each delete. Run daily by [`/api/reconcile-dupes`](../../app/api/reconcile-dupes/route.ts) (15:30 UTC, after scrapes, before the audit). **Live since 2026-07-01** (`RECONCILE_EXECUTE=true` in Vercel production; it ran report-only from 2026-06-09 to 06-30 plus 14 manual one-off merges). Unset the env to fall back to dry-run; `?execute=1` forces a one-off. Every merge is reversible: `INSERT INTO hwy4_events SELECT (jsonb_populate_record(null::hwy4_events, merged_snapshot)).* FROM event_merge_log WHERE merged_from_id = '…'`. **Merged-away URLs don't 404:** the detail page's stale-slug recovery (`findEventFallback` in [lib/events.ts](../../lib/events.ts)) consults `event_merge_log` *ahead of* the fuzzy name matcher — it recomputes each same-date snapshot's slug for an exact loser-slug → survivor mapping (following a short survivor-was-later-merged chain; service-role read since the table is RLS-locked, degrades to a plain 404 without the key), so a shared/indexed link to a reconciled loser 301s to the survivor instead of dying. Locked by the `matchMergedSlug` cases in `scripts/test/events-fallback.test.ts`.
4. **Backfill + audit** — [scripts/backfill-dedup.ts](../../scripts/backfill-dedup.ts) is a thin CLI wrapper over the same `reconcileDuplicates` engine: `tsx backfill-dedup.ts` (dry-run) / `--execute` (apply). Needs `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`. `/api/check-events` reports same-event dupes (venue+time, different title) that the old name-only check missed, plus a `merges_last_24h` count.

The "same event" rule is defined **once** in `lib/event-identity.ts` (`isSameEvent`, locked by `scripts/test/event-identity.test.ts`) and reused everywhere via `lib/dedupe-events.ts` (`clusterEvents`/`pickSurvivor`): the read-time assertion, the write-time merge (`scripts/lib/dedup.ts`), the reconcile engine, the backfill, and the audit all import it, so the definition can't drift.

**End-time forgiveness + locality-venue strip (2026-07-05, the Coffee & Cars triple):** three sources listed the same Meadowmont Lodge car show with three different extracted end times (11:00 / 17:00 / 12:00 — Visit Murphys' own description said "8am to 11am" while its structured end said 5pm), and the old ends-must-agree-when-both-known rule was a hard veto, so every dedup layer was blind to the triple for six weeks. Now `timesAnchor` forgives a conflicting known end **when the venues agree** (name fuzzy or street-number anchor): same venue + same date + same start is one physical slot, so a differing end is scrape noise. When the venues *don't* provably agree (one side unknown), conflicting ends still split the rows. Separately, `venueForMatch` strips a Facebook-style trailing locality (`"Meadowmont, California"` → `meadowmont`, comma required) so the place core can fuzzy-match the real venue (`Meadowmont Lodge`) instead of tripping the different-venues veto; when the remainder is just the event's own town (`"Arnold, California"`), the venue is treated as unknown (mergeable on title/artists/description, but never able to anchor a venue-based signal). Both locked in `scripts/test/event-identity.test.ts`; a full-catalog dry-run at ship time confirmed the triple was the only cluster the loosening added.

**Series-placeholder start-time forgiveness (2026-09-19, the Brice Hilltop pair).** `isGenericTitle` already classifies "Brice Station Vineyards – Hilltop Concert Series" as a series placeholder, so the generic-title path would merge it with a named act at the same venue **if the starts agreed**. They did not: Brice's own ticket product listed Greg Sutton at 6:00 PM ("one hour earlier than our usual start time") while GoCalaveras kept the series default 7:00–10:00 PM and a leftover Earth Tones Trio from a prior EventON occurrence. Exact-start was a hard veto, so write-time merge, reconcile, and the (retired) read-time collapse were all blind at once. `timesAnchor` now allows a start to disagree by up to `GENERIC_SERIES_START_TOLERANCE_MIN` (90) **when the venues agree AND exactly one title is generic**. Two named acts an hour apart stay split; two generic titles at different hours stay split (the existing 3 PM vs 7 PM Live Music guard). Merge-time, an actless-placeholder row must not donate its leftover artists, series-default clock, EventON description, aggregator URL, or sid onto a named-act survivor (`mergeArtistLists` + `placeholderNameSteal` in `buildStrongMatchUpdate` / `buildFill`). **Exact `source_event_id` is a second copy of the hole:** GoCalaveras's EventON id hits the Hilltop row first, so a re-scrape never reached fuzzy merge. `namedActTakesPrecedence` skips that exact-key write when a named-act sibling already matches (`org_slug === venue_key` is never deferred, so the organizer can still write; a placeholder with no named-act sibling still inserts). Locked by `scripts/test/event-identity.test.ts` + `dedupe-events.test.ts` + `null-guard.test.ts`. Live upcoming blast radius of the start-drift hole at ship time: 1 pair (today's Brice night, already `visibility=private`). No other upcoming GoCalaveras Hilltop row exists. Arnold Angels Music Festival (2026-10-04) is a charity festival **at** Brice Station, not a wrong `venue_key`. A sibling pattern — Facebook Discover's "Coppertown Square" vs the registry's "Copperopolis Town Square" — was a venue-key miss of the same series-vs-slot class; alias added.

**Town is a label, not an identity key (2026-07-28, the Doc Nancy dupes).** A community submission put Calaveras Big Trees State Park in **Camp Connell**; the park's own listing says **Arnold** (its mailing address). Same program, same night, same 8:00 PM start, two cards on the homepage. Town was a hard veto at the top of `isSameEvent` **and** a component of the read-time bucket key, so the read-time collapse, the write-time merge, the nightly reconcile, and the triage agent's candidate query were **all** blind to it at once. The corridor is one continuous string of settlements along Highway 4 and several venues sit near a boundary, so the town label is a human guess on *both* sides of the comparison. Four changes: (1) the town veto now fires **only when the venues do not provably agree** — a shared `venue_key`, a venue-name match, or a street-number anchor outranks a differing label, and the usual identity signal is still required on top; (2) `venue_key` joined `EventIdentity` as the strongest venue signal (registry-resolved, immune to spelling), and `venueTokensAgree` fuzzy-matches a venue rewritten from both ends at once ("Calaveras Big Trees State Park" vs "Big tree State Park overlook") at a deliberately high bar (≥3 shared distinctive tokens AND ≥80% of the smaller name, which still rejects "Bear Valley Lodge" vs "Bear Valley Adventure Company"); (3) `bucketKey` in `lib/dedupe-events.ts` **dropped town** — it was the last silent second copy of a rule that lives in the predicate, the same failure shape as the `start_time` component HWY-10 removed, and no loosening inside `isSameEvent` could be reached through it; (4) `titlesShareTokens` discounts venue words when the venues agree, as a **second chance only** (never a replacement — venue words shared by both titles are shared tokens, and removing them can only lower Jaccard, so a strip-instead-of-add would silently un-merge existing matches). That last one caught a **second** duplicate from the same submitter the same week ("Optical astronomy big tree State Park" vs "Optical Astronomy Nights @ Big Trees State Park"), where one source separates the venue with "@" and the other runs it into the title. Full-catalog dry-run at ship time: over the entire upcoming set, exactly 6 pairs clear a superset of the matcher's gates, all 6 genuine duplicates, and the only **new** merges are the 2 community dupes. Both were merged reversibly via `event_merge_log`. Locked by `scripts/test/event-identity.test.ts` + `dedupe-events.test.ts`.

**An identical start-AND-end window is its own identity signal (2026-08-11, the Rotary shrimp feed).** Two aggregators listed the Angels-Murphys Rotary shrimp feed at Murphys Community Park on Aug 15, both 16:00–21:00, both resolved to `venue_key='murphys-community-park'` — and every text signal missed by roughly half: titles 0.33 against the 0.85 bar ("Rotary's Annual Shrimp Feed & Auction" vs "Annual Shrimp & Pasta Feed Fundraiser"), descriptions 0.27 against 0.92, description token overlap 0.25 against 0.70, title tokens 0.375 against 0.60, both `artists` arrays NULL. Each source wrote its own title *and* its own prose, so there was no shared string structure to grab. Because all four layers reach the one predicate, the pair was simultaneously invisible to the read-time collapse, the write-time merge, the nightly reconcile **and** `/api/check-events` (which reported `same_event_duplicates: 0` while both cards sat on the homepage — `findDuplicateClusters` is just `clusterEvents(...).filter(c => c.length > 1)`, so the audit is not an independent check for this class, and the one predicate-free check, `timeless_near_dupes`, only fires when a NULL-start row is involved). `sameExactWindow` adds the last-resort signal: same venue + start AND end both known on both sides and both equal. **The end time is what makes it safe, and it is not a detail** — measured over the whole upcoming catalog, same-venue + same-date + same-**start** yields 6 pairs of which only 1 is a duplicate; the other 5 are Calaveras Big Trees genuinely running Junior Rangers, Meadow Walk and the South Grove Guided Hike all at 10:00 in the same park, so merging on the start alone would have silently deleted four real programs. Requiring both ends known and equal leaves exactly the 1 true duplicate (the park's programs are different lengths). A NULL end on either side never matches — treating NULL as equal re-admits the Big Trees pairs. **Naming different acts disqualifies the window outright**: a venue can run a Salsa Night with Los Caminos and an Open Mic with Jane Doe in the same 19:00–21:00 slot, and two rows that each name an act and disagree on who is playing are asserting two different shows, which outranks the matching clock. Ship-time dry run: 25 upcoming pairs share an exact window, 24 die at the different-venues veto (no street-number coincidences), and the 1 that reaches the new signal is the shrimp feed. Merged reversibly via `event_merge_log`. Locked by `scripts/test/event-identity.test.ts`.

**A shared press release outranks a venue nobody can name (2026-09-04, the Calaveras wine-trail dupe).** A region-wide event has no single venue to agree on. The "Red, White & Rosé Tasting Experience" runs across 13 tasting rooms on one ticket, so GoCalaveras filed it under the alliance's ticket office ("Calaveras Winegrape Alliance Information Center", 106 Main Street) while Visit Murphys filed it under a stretch of road ("Hwy 4 and Main Street Murphys"), and the two disagreed on the start by an hour (10:00 vs 11:00) because neither is a real door time — the organizer states only a 10am–4pm *wristband pickup* window. The event's own shape therefore destroyed both anchors at once: every venue-gated signal was unreachable (`bothVenuesKnown && !venuesAgree`) and `timesAnchor` failed on the differing start, so the pair died before reaching the description test it would have passed easily (similarity **0.949**, byte-identical after the opening clause). Invisible to all four layers, and to `/api/check-events` as well, for the usual reason: `same_event_duplicates` shares the predicate. `sharedPressRelease` adds the signal: descriptions ≥200 chars and ≥0.92 similar, **gated on the venues NOT agreeing**. That inversion reads backwards next to every other signal here and is the entire point — when two sources cannot agree what to call the place, the clock is not evidence and the copied text is; when they DO agree on the venue the clock is meaningful and must match, because Murphys Creek Theatre runs "An Act of God" at 14:00 and again at 19:30 on 2026-12-19, two real performances sharing one synopsis that this path must never merge. Naming different acts still disqualifies, per `sameExactWindow`. The 200-char floor keeps short boilerplate ("Live music in the beer garden") out, since it repeats across genuinely different events. Ship-time dry run over the whole upcoming catalog (every same-date same-town pair with descriptions ≥150 chars, pg_trgm recall filter at 0.25): **exactly one pair clears 0.92**, the wine trail at 0.952; the next is 0.526 (a same-venue pair the existing paths already own) and everything else is ≤0.28, so the margin is ~0.43. Locked by `scripts/test/event-identity.test.ts`, including the matinee/evening non-merge. **The live pair was resolved by cancelling the GoCalaveras row, not deleting it** — a delete is re-inserted by the next aggregator pass, while no scraper update path writes `status`; the survivor (Visit Murphys) carries the organizer's real name, the Labor Day poster and the $25–$40 price, back-filled with the loser's pickup address.

**Match-time normalization + address anchor (2026-07-04, the Arts & Crafts Festival dupe):** title/description similarity compares via `normalizeForMatch` — `normalizeName` plus "&"→"and" folding and a leading "Nth Annual"/"Annual" strip — so "54th Annual Sierra Nevada Arts & Crafts Festival" matches "Sierra Nevada Arts and Crafts Festival". This is deliberately NOT applied in `generateDedupKey`: changing that hash would orphan every stored dedup_key and re-duplicate the catalog on the next scrape (key stability is test-locked). Separately, the different-venues veto is softened by a **same-street-number address anchor** (`sameStreetNumber`): two sources naming the same lot differently ("Bristol's Ranch House Cafe" vs "Bristols's Cafe Parking Lot", both at 961 Highway 4) no longer trip the veto. The anchor needs a ≥2-digit street number on both rows and never merges on its own — one of the usual identity signals (title / artists / description / generic-title / act-named) is still required.

> **Dedup Move 3: COMPLETE (2026-08-23).** Step 1 (assertion) shipped 2026-08-11 via HWY-16; Step 4 (full removal) shipped 2026-08-23. The gate as ratified was "assertion never fired"; what was actually verifiable (and what the removal rests on) is the layer-1 paragraph above: zero persistent duplicates for a week, two transient same-day-healed transits, and the accepted ~7.5h morning transit window. Render paths carry no dedup logic; detection lives in the daily audit's predicate-independent checks + `merges_last_24h`.
