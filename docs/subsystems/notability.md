## Event Notability (hide routine venue operations)

Some venues publish their own restaurant/lodge calendar, so their day-to-day operations leak in as fake "events": Sequoia Woods Country Club lists a weekly **"Thursday Night Dinner"** and **"Wednesday Night Deli Special"**; the Moose Lodge lists recurring dinners/breakfasts and "open for [holiday]" meals. Being open to serve a meal is not an event; a special occasion with a hook (live music, a guest, a theme, a one-off) is. A `is_routine` flag hides the former from every public surface while keeping the latter.

- **The judgment lives once in [lib/notability.ts](../../lib/notability.ts)** (`classifyNotabilityDetailed` + `reconcileNotability`), structured exactly like `lib/categorize.ts`: a **Tier-0 notable hook** (`category==='live_music'`, or tokens like car show / karaoke / featuring / trivia / fundraiser / scramble / crab feed) that **beats** the routine floor — so "Special Monthly Dinner **with Live Music**" stays — then a **Tier-1 authoritative routine** floor (`<weekday> [night] <meal>`, deli/daily specials, named nights, "open/serving for <holiday>", holiday-meal, and title-leading "Private <party/event/rental>" hall rentals, added 2026-07-17) that an LLM cannot lift, then a **Tier-2 soft** tier (bare `brunch`/`buffet`, or `is_weekly` + a meal noun) the LLM may confirm or clear. **Bare `dinner`/`lunch` is deliberately NOT soft-routine** — real events say "…/ Dinner" (e.g. the "Sequoians Summer Scramble SG / Dinner" golf event stays). Locked by [scripts/test/notability.test.ts](../../scripts/test/notability.test.ts).
- **Columns on `hwy4_events`:** `is_routine` (the hide flag), `notability_locked` (human override — when true no writer touches it, mirrors `price_locked`/`description_locked`/`poster_locked`), `routine_reason` (which rule / `"llm"` fired, audit only). Migration `20260701c_add_notability.sql`.
- **Blast-radius invariant — ONLY `sequoia-woods` + `moose-lodge` ever set `is_routine=true`.** The floor runs inside the shared `upsertEvents` (`scripts/lib/dedup.ts`, `OPERATIONAL_ORG_SLUGS` gate) so Sequoia + the Moose public-events page are covered with no per-scraper edit; the self-contained Moose PDF route (`app/api/scrape-moose-lodge/route.ts`) does its own floor + an `is_routine` LLM field, reconciled by the floor. Every other source writes `false`. **Do NOT wire the flag into any other scraper** — the read filter is global and trusts that only these two venues populate it. Self-heals + is reversible per row like the other locks (`UPDATE … SET is_routine=false, notability_locked=true WHERE id=…`).
- **Read-time hide:** `.neq('is_routine', true)` on the shared `getUpcomingEvents` fetch ([lib/events-data.ts](../../lib/events-data.ts)) covers the homepage, town pages, temporal pages, and sitemap, with **no private exemption** (HWY-45). A private exemption used to keep lodge meals for the Clubs view, but the detail lookup ([lib/events.ts](../../lib/events.ts)) 404s `is_routine` with no such exemption, so those cards 404'd on every list that did not also gate visibility. The by-slug/fallback lookups use the same `.neq`, so a hidden event's detail page **404s** (consistent with cancelled). The three standalone queries that bypass the shared fetch also filter it: `app/api/generate-briefing`, `app/api/generate-weekend-briefing`, and `lib/newsletter.ts`. `is_routine` is selected on the shared fetch so the client predicate can drop a row the SQL missed; cards do not render the flag. **Members-only rows** (`visibility='private'`, not routine) stay in the fetch for the homepage Clubs toggle and are gated by one predicate, [lib/list-visibility.ts](../../lib/list-visibility.ts) `filterListableEvents` / `isListableEvent`: empty `enabledOrgs` hides them. Homepage `EventList` is the only surface that fills that set. Temporal pages, stay-range links, town pages, and `SimpleEventList` call the same helper with nothing opted in, so a new list cannot show a "Members & Guests" card by forgetting the gate. Locked by `scripts/test/list-visibility.test.ts`.
- **Backfill existing rows:** `cd scripts && npx tsx backfill-notability.ts` (dry-run) / `--commit` (apply) — scoped to the two orgs, skips `notability_locked`, floor-only (no LLM). One-time; new scrapes self-heal via the write path.
